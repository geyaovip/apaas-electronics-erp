# 技术与数据设计

- 前端 React + TypeScript + Vite；后端 NestJS + TypeScript；PostgreSQL + Prisma。每个应用有独立数据库、迁移和进程。
- 独立部署自动创建本地管理员，由管理员建立角色账号；成员可凭旧密码修改密码并注销全部会话。办公平台登录不是运行前提。
- 数据对象：租户、用户、会话、客户、商机、产品、供应商、采购单及明细、销售合同及明细、库存余额、库存流水、应收、应付、收付款、审计日志。
- 订单状态更新采用版本号与事务。入库和出库在同一事务中更新单据、库存、流水及账款；库存扣减使用条件更新防止并发超卖。
- API 前缀 `/api/v1`，错误带机器码与请求 ID。列表分页，每次读取服务端当前状态。
- 第三方连接仅保留边界；未进行真实授权和收发验收之前展示未接入。
- AI 接口 `/api/v1/ai/status`、`/conversations`、`/chat` 使用当前会话读取经营概览、采购单或销售合同；对话按租户和用户持久化并可删除。合同风险上下文读取库存；只有原本可查看采购的角色才会得到未收采购行。无密钥时返回 503，模型建议不触发出入库或财务写入。
- `GET /ai/risk-reviews/:type/:id` 与 `POST /ai/risk-reviews` 提供当前采购单或销售合同的结构化履约分析。后端独立计算未收量、待发量、当前库存与差额；模型只解释并建议人工核实。结果按当前数据快照验证并写审计，数据变化后旧结果不再作为当前结果展示。
