# 电子行业 ERP 产品需求

## 首期闭环

管理客户与商机、电子产品 SKU、供应商；从采购单确认到入库与应付，从销售合同确认到出库与应收，再记录收付款。每个业务动作必须留下状态、金额、库存流水和审计记录。金额使用 CNY，两位小数。数量使用正整数（件）。

## 角色

- 管理员：全部业务与成员管理。
- 销售：客户、商机、销售合同；只能查看自己的客户和合同。
- 采购：供应商、采购单。
- 仓库：入库、出库、库存。
- 财务：应收应付和收付款。

## 业务约束

- 采购单和销售合同明细以创建时产品名称、SKU、单价形成快照；总金额由服务端计算。
- 采购单确认后才能按行分批入库，每批有入库单、库存流水和实收数量；超收被拒绝。应付按每批实收金额累计，全部收完才标记采购完成。
- 销售合同确认后才能按行分批出库，每批有出库单、库存流水和已发数量；库存不足时该批事务全部回滚，超发被拒绝。应收按每批实发金额累计，全部发完才标记合同完成。
- 仓库可对现有产品盘点，记录盘点单及差异流水；库存变化时盘点拒绝覆盖新数量。产品可设置低库存提醒阈值。
- 每笔收付款大于零，不得超过未结清金额；同一账款的付款参考号不得重复。单据状态、批次、付款历史与账款余额可追溯。停用商品不得用于新单。
- 操作权限与租户隔离在服务端执行，不依赖前端隐藏按钮。

## 后续范围

复杂 BOM、税率及多币种、发票、退货、批次/序列号追溯、多仓库与三方办公平台接入尚未实现。
